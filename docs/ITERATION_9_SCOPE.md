# Iteration 9 receiving scope (before implementation)

Review baseline: merged fork-buffer PR #9, main `6b38561`, and terrain design PR #8 `ae5666c`. The GPT-6.1 Sol [research review](ITERATION_9_RESEARCH.md) found no blocker for this independent data experiment. The 11 geometry/buffer tests were rerun successfully locally. The [visual geometry review](GEOMETRY_VISUAL_REVIEW.md) closes the imagery check, with synthetic linkage dimensions explicitly unvalidated.

Deliver R0a: a separate prescribed-motion terrain-request station and shared Node replay. This is the first receiving subset of [R0](TERRAIN_SAMPLING_CONTRACT.md), not its entire gate. Use synthetic 2 cm cells, immutable static layers, explicit rectilinear rock faces, finite-width continuous swept bounds, optional lookahead, shared asynchronous tile caching, owned extraction arrays, stale/reset protection, missing-data admission and bounded memory/work. Accepted motion is piecewise linear in position and heading; no free-motion uncertainty or dynamics is inferred.

Before judging results: exact source-cell identities and span values on hand-authored plane/ramp/step fixtures; normals within 1e-12; swept bounds contain independently sampled intermediate corners within 1e-12; mirror/reverse/stationary controls; no admission for missing/deep/outside/over-budget requests; out-of-order/reset/failure safety and immutable old readers; deterministic complete replay and browser/Node JSON equality. Preserve the full prior suite and inspect desktop/mobile captures.

Resource defaults: 4096 extracted columns, 12288 spans (at most three each), 32 source tiles, eight pending tile loads, four concurrent requests. Source tiles contain 40×40 cells; each typed-array tile uses 97600 bytes. Outputs own copies, so cache eviction cannot mutate readers; at most four outputs may be retained by a caller only if the caller follows its own storage budget. The replay itself retains at most 24 bounded extracts. This offline experiment makes no real-time or allocation-free integration claim.

Deferred R0 gates: raster import and arbitrary transforms; resolved root bodies/reinforcement, overhangs and void fixtures; probabilistic/multimodal or asymmetric route prediction; shared mutable snapshot membership; leased zero-copy outputs; interactive editing of source metadata; wall-clock-independent availability-event replay. R0a replay preloads or deterministically awaits required data and records accepted geometry, not network timing. Later R1–R3 receive tyre deformation/contact, layered shared soil history, rolling 3D traction and measured fidelity transfers. Shock/rider stops, component loads/failure and source-backed production-bike geometry remain separate dynamics follow-ups.
