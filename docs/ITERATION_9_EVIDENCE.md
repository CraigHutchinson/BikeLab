## Delivered R0a

`terrain-request.html` and `scripts/terrain-request.mjs` consume the same pure module. Six tracks prescribe piecewise linear position/yaw, 24 intervals of 50 ms: straight, left/right turn, reverse, stationary steering and unknown-cell hold. The station shows top-down required/optional coverage, resident tiles, finite wheel width, 3D source features and longitudinal/transverse layer cutaways. Play/pause, step, scrub, rewind, delayed loading/cancellation and JSON verification are exposed. Export contains complete accepted arrays and request identities; import rebuilds the declared static source and rejects differences.

The synthetic source is an 8 × 3.2 m local grid, 2 cm cells at centres, 40 × 40 cells/tile, x forward/y left/z up. Source and material revision 1, immutable epoch 0 and fixed identity transform are the only supported state. Known vertical coverage is −0.20 to +0.20 m, with air above each top surface. No scan importer, mutable soil or constitutive parameters are implied. Source material names are labels. Source tiles use 97,600 typed-array bytes; defaults bound resident storage to 3,123,200 bytes, eight pending loads, four active requests, 4,096 output columns and 12,288 spans/request. The replay retains at most 24 owned outputs. Object/record overhead is additional; these are count/array bounds, not measured memory or latency budgets.

Required coverage encloses all linearly interpolated poses, including heading change. For envelope corner radius R and heading change Δθ, the endpoint box is inflated by R|Δθ|/2: linear translation lies in its endpoint hull, and the rotation's deviation from the interpolated endpoint vectors is at most 2u(1−u)R|Δθ|. Retained lookbehind follows actual displacement; at zero translation it retains the initial heading's rear side. This is conservative for the prescribed trajectory, not a certificate for unknown dynamic motion. Optional lookahead has no calibrated probability and cannot shrink mandatory coverage.

Extraction preserves canonical cell IDs, Float64 coordinates/top/normals, Uint32 span offsets, ordered nonoverlapping material spans and explicit rock boundary vertices/faces. The stepped rock is one extruded polygon, so its vertical face remains at x=6 with outward normal (−1,0,0), including buried and exposed portions. A separate off-centre edge at y=0.12–0.14 m verifies width coverage. Geometric cells are not loaded tyre contact area; no contact forces or pressure are computed. The cutaway displays the authored source with delivered columns marked separately.

Identical tile loads deduplicate across wheels. Every response owns its extraction arrays; eviction cannot change old readers. Source fixture, static epoch, format, run generation and monotonic per-wheel sequence are validated; reset/cancel/late results cannot publish a stale extract. Missing cells, unknown depth, source boundaries, resource limits and loader failure cannot report complete. Over-budget mandatory requests return pending/unsupported, while optional clipping is explicit. No physics advancement occurs while awaiting required data.

## Remaining gates

This is **R0a**, not completion of [R0](TERRAIN_SAMPLING_CONTRACT.md). Multimodal/asymmetric probabilistic ribbons, arbitrary source transforms/raster imports, resolved roots/composites/voids/overhangs, mutable snapshot membership and leased zero-copy results remain unimplemented. Replay deterministically awaits required static data; wall-clock availability events are not reproduced. Returned owned arrays remain the caller's storage responsibility. No solver loop is allocation-free or benchmarked here.

R1–R3 still require a deformable distributed tyre, force/moment/work references, layered shared soil history, mud ownership, rolling 3D combined traction, calibrated component damage and verified adaptive-rate/fidelity transitions. Existing bicycle forces, fork travel guards and supported stop limits remain unchanged. Full shock/rider attachment stops and source-backed production-bike geometry are separate follow-ups.


## Hosted review corrections

Initial head `942396e` passed all 116 tests on Ubuntu and Windows in [run 38909011962](https://github.com/CraigHutchinson/BikeLab/actions/runs/38909011962). Chromium exposed a last-bit difference in a turning swept-box coordinate: −0.03947548956610583 versus −0.039475489566105824 m. The originally requested exact cross-runtime JSON gate was too strong for trigonometric geometry. Comparison/import now applies the already declared 1e-12 geometric budget only to floating geometry/time fields; IDs, cells, masks, offsets, counts, revisions, status and schema remain exact. Tests distinguish tolerated floating error from real geometric or identity corruption. Same-runtime replay remains identical. This threshold correction is explicit, not an exact-equality claim.

Read-only GPT-6.1 Sol review found a receiving-run lifecycle gap: repeated clicks could retain multiple cancelled loads. Calculation/import are now serialized by an active-operation guard and disabled initiation controls until pending work settles. Publication cancellation remains immediate. A subsequent independent face-winding check corrected polygon winding to agree with outward normals; pending source-queue exhaustion now reports a wait rather than I/O failure. These corrections have focused regressions.
